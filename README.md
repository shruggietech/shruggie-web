# shruggie-web

The official [ShruggieTech](https://shruggie.tech) website — a Next.js
marketing and content site covering our services, case studies, blog, and
open-source products.

## Tech Stack

| Layer | Technology |
|---|---|
| Framework | [Next.js](https://nextjs.org) (App Router, React Server Components) |
| Language | TypeScript (strict mode) |
| Styling | [Tailwind CSS](https://tailwindcss.com) 4.x |
| Motion | [Framer Motion](https://motion.dev), [GSAP](https://gsap.com), [Lenis](https://lenis.darkroom.engineering) smooth scroll |
| Blog content | MDX via `next-mdx-remote/rsc`, syntax highlighting via [Shiki](https://shiki.style) |
| Contact form | [Formspree](https://formspree.io) + React Hook Form + [Zod](https://zod.dev) validation |
| Analytics | Google Analytics 4 + Google Tag Manager (consent-gated) |
| Deployment | [Vercel](https://vercel.com) |

The full, authoritative specification for page structure, design tokens, and
content requirements lives in
[`ShruggieTech_Website_Specification.md`](ShruggieTech_Website_Specification.md).

The accepted but not-yet-shipped editorial backend architecture is documented
in [`docs/architecture/adr-001-firebase-editorial-backend.md`](docs/architecture/adr-001-firebase-editorial-backend.md),
with production procedures in
[`docs/operations/firebase-production.md`](docs/operations/firebase-production.md).

## Getting Started

**Prerequisites:** Node.js 22 LTS or newer, npm. (Next.js 16 requires Node
&ge;20.9.0 at minimum per `package-lock.json`, but Node 20 has since reached
end-of-life — use an actively maintained LTS release.)

```bash
# Install dependencies
npm install

# Copy environment variables and fill in the values you need
# (GA4/GTM IDs, Formspree form ID — see ShruggieTech_Website_Specification.md §10.2)
cp .env.example .env.local

# Start the dev server at http://localhost:3000
npm run dev
```

### Available Scripts

| Command | Description |
|---|---|
| `npm run dev` | Start the local development server |
| `npm run build` | Production build |
| `npm run start` | Serve the production build |
| `npm run lint` | Run ESLint |

Before opening a PR, also confirm the build type-checks cleanly:

```bash
npx tsc --noEmit
```

## Project Structure

```
app/            Route segments (App Router) — one folder per page, plus
                api/, sitemap.ts, robots.ts
components/     Shared React components, grouped by domain
                (ui/, shared/, layout/, about/, blog/, home/, products/)
content/        MDX content — blog/ posts and work/ case studies
lib/            Data access and utilities (blog, case studies, schema, etc.)
public/         Static assets (images, fonts, favicons)
styles/         Global CSS and design tokens
.specify/       Spec-kit configuration, templates, and project constitution
specs/          Feature specs/plans/tasks generated by spec-kit (created as
                features go through the workflow below)
```

## Content Authoring

- **Blog posts** are MDX files in `content/blog/`. Frontmatter fields and the
  rendering pipeline are documented in `ShruggieTech_Website_Specification.md`
  §7.
- **Case studies** are MDX files in `content/work/`.

## Contributing

Feature-sized work follows spec-kit's Spec-Driven Development workflow,
gated by the project constitution at
[`.specify/memory/constitution.md`](.specify/memory/constitution.md)
(specification precedence, design-system reuse, WCAG 2.2 AA accessibility,
and the Core Web Vitals performance budget):

```
/speckit-specify   → describe the feature
/speckit-clarify   → resolve ambiguity (if needed)
/speckit-plan      → generate the implementation plan
/speckit-tasks     → break the plan into tasks
/speckit-analyze   → check cross-artifact consistency (optional)
/speckit-implement → execute the tasks
```

Trivial one-commit changes (typos, copy fixes, dependency bumps) can skip the
full workflow. For everything else:

- Match the existing design system — reuse tokens and components under
  `components/ui/` and `components/shared/` before adding new ones.
- Every interactive element must be keyboard-reachable, every image needs
  appropriate `alt` text, and every animation must respect
  `prefers-reduced-motion`.
- Run `npm run build`, `npx tsc --noEmit`, and `npm run lint` before opening
  a PR.
- Update `CHANGELOG.md` for user-facing changes.
- Commit messages follow `<scope>: <imperative description>` (e.g.
  `web: add CTA to blog article template`).

Pull requests are automatically reviewed by an AI code review bot in
addition to human review — address its comments the same as any other
reviewer's.
